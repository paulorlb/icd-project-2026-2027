# ICD project: GOVCOPP publications (2020–2026)

This project reproduces an analysis of publications associated with GOVCOPP researchers. The W06 notebook checks the source files, builds a coauthorship network, and describes ties between formal groups. All paths start from the project root.

## Structure

```text
data/raw/                 unchanged source CSV files and their description
data/processed/           datasets generated by code
notebooks/W06S01_practice.ipynb
notebooks/aulas/          local copy of the teacher solution
src/icd_project/          reusable functions
outputs/w06/             results generated by the W06 notebook
```

Each future class notebook should write to its own subfolder under `outputs/`.

## Set up the environment

Open the project root in VS Code. In a terminal at that root, run:

```powershell
conda env create -f environment.yml
conda activate icd-project
python -m pip install -e .
python -c "import sys; print(sys.executable)"
```

If `environment.yml` changes, run `conda env update -f environment.yml --prune`. In VS Code, select the `icd-project` interpreter and notebook kernel. Check that `sys.executable` in the notebook points to the same environment.

## Data

The three CSV files were supplied with this project. The [source description](data/raw/README.md) explains their contents, units of observation, separators, and limitations. The extraction date and redistribution rights are not documented. The CSV files stay in the local `data/raw/` folder and are excluded from Git.

In a fresh clone, obtain the original files from the team that supplied the dataset and place them in `data/raw/` without resaving them:

| File | SHA-256 of the version used here |
|---|---|
| `authorship_2020_2026.csv` | `512f30215fe028935fc599667a6632e017f99f6d9f77f2892258e7f555c66338` |
| `publications_2020_2026.csv` | `badca2d7219a3f5b14a2c9f6f7b100a4c094ffe0dcbe6431a966a0471c3b7362` |
| `publications_authors_2020_2026.csv` | `526c9e6e3b3861f14ecaa6528a0eca5baf2c129c252b136df0b2f5dc2dbe538c` |

The W06 notebook uses the first two files. They correspond, respectively, to the class files `teaching_authorship_2020_2026_textual.csv` and `teaching_publications_2020_2026_textual.csv`. The third file is an optional integrated table; it uses `;` as the separator and starts with `sep=;`.

These local CSV files assign one researcher to `PI3`. The teacher solution, kept locally in `notebooks/aulas/`, uses a later correction to `PI2`. Overall counts agree, but some group counts differ. The teacher solution and its embedded outputs are excluded from Git. The project notebook uses the hashes and reference values for the local files.

## Run and verify

1. Open `notebooks/W06S01_practice.ipynb` with the `icd-project` kernel.
2. Use **Restart Kernel → Run All**. The notebook locates `environment.yml` from the working directory, checks the inputs and checkpoints, and writes the results.
3. Inspect `outputs/w06/coauthorship/`. Running the optional extension also creates `outputs/w06/coauthorship_min_weight_2/`. These files are generated; do not edit them by hand.

The original teacher notebook in `notebooks/aulas/W06S01_practice_solution.ipynb` expects the `teaching_*_textual.csv` filenames and the corrected affiliation. It is a local reference and is absent from a fresh clone.

## Limits and decisions

- The 2026 records may be incomplete; the extraction date is unavailable.
- `publication_id` identifies publications. An authorship row represents one publication–researcher relationship. Joining the two tables increases row count; joined rows are not a count of publications.
- The source CSV files are never transformed by hand. `data/processed/` and `outputs/` contain regenerable results. Git records code, documentation, and the adapted notebook while excluding source data without documented redistribution rights, local environments, secrets, and generated results.
