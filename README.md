# ICD project: GOVCOPP publications (2020–2026)

This project is the reference repository for the Introduction to Data Science course project. It
also contains teacher-maintained practice material. The W06 notebook checks the source files,
builds a coauthorship network, and describes ties between formal groups. All analytical paths are
built from the project root.

## Purpose and ownership

Keeping teacher material and group work in different locations allows the teacher to publish
updates without silently replacing student work.

| Path | Owner | Rule |
|---|---|---|
| `notebooks/lessons/` | teaching team | Canonical lesson sources; groups do not edit these files |
| `notebooks/project/` | student group | Group adaptations and project notebooks |
| `docs/`, `reports/` | student group | Decisions, contributions, evidence and written deliverables |
| `src/icd_project_aux/` | shared | Reusable code; add new modules where possible instead of changing lesson helpers |
| `data/raw/` | local input | Read but never edit by hand; files are excluded from Git |
| `data/processed/`, `outputs/` | generated | Recreate with code; never retouch generated files |

## Structure

```text
data/raw/                         local source data; read, never edited by notebooks
data/processed/                   analytical datasets generated by code
notebooks/lessons/                teacher-maintained lesson notebooks and their static assets
notebooks/project/                group-owned project notebooks
src/icd_project_aux/              reusable functions
docs/                             research records, evidence and contribution logs
reports/                          group-written deliverables
scripts/                          repository checks and setup helpers
outputs/lessons/w06/              generated results from the W06 lesson notebook
outputs/project/                  generated results from group project notebooks
```

Static images used by lesson notebooks live beside them in `notebooks/lessons/_assets/`; they are
versioned source material, not generated output. Each lesson writes to its own subfolder under
`outputs/lessons/`. Group notebooks belong in `notebooks/project/` and should write generated
results under `outputs/project/`.

## Set up the environment

Open the project root in VS Code. In a terminal at that root, run:

```powershell
conda env create -f environment.yml
conda activate icd-project
python -m pip install -e .
python -c "import sys; print(sys.executable)"
python -c "from icd_project_aux.data import read_table; print(read_table.__module__)"
```

The `icd-project` environment installs the `icd_project_aux` helper package from `src/`.

If `environment.yml` changes, run `conda env update -f environment.yml --prune`. In VS Code, select the `icd-project` interpreter and notebook kernel. Check that `sys.executable` in the notebook points to the same environment.

## Create the group working notebook

Do not edit the canonical notebook in `notebooks/lessons/`. Create a group-owned copy with:

```powershell
python scripts/start_group_notebook.py W06S01 group-name
```

This creates `notebooks/project/W06S01_group-name.ipynb`, clears teacher execution results, points
static image references back to the lesson assets, and changes the generated-output destination
from `outputs/lessons/w06/` to `outputs/project/w06/`. The command refuses to overwrite an existing
group notebook.

## Run order

1. Open the repository root in VS Code.
2. Create or update the `icd-project` environment and install the package with `python -m pip install -e .`.
3. Put the documented source files in `data/raw/` and run `python scripts/verify_repository.py`.
4. Create the group notebook with `scripts/start_group_notebook.py`, if it does not already exist.
5. Open the group notebook with the `icd-project` kernel and confirm `sys.executable`.
6. Use **Restart Kernel → Run All** and resolve the first failing checkpoint, if any.
7. Inspect `outputs/project/w06/coauthorship/`; do not edit generated files by hand.
8. Update the records in `docs/`, inspect `git diff`, and commit one coherent verified change.

The original teacher solution is available in the course materials. This repository uses
`notebooks/lessons/W06S01_practice.ipynb` as its single teacher-maintained W06 notebook.

## Generated and reference outputs

Everything under `outputs/` is regenerable and is intentionally excluded from Git, apart from the
placeholder that keeps the directory visible. Correct the code and rerun the workflow instead of
retouching a CSV or figure in place. If the course later distributes selected small reference
results, store them separately under `reference/expected_outputs/<lesson-id>/` with a README that
states how and from which input version they were produced.

## Project records

- `docs/research_plan_v0.md` states the question, units of analysis, data, strategy and risks.
- `docs/evidence_register.md` links each claim to an output, unit, denominator, check and limitation.
- `docs/contributions.csv` records who performed and checked each contribution.
- `docs/ai_use_log.csv` records the request, resulting change, independent check and decision.
- `reports/` contains written deliverables, not generated analytical tables or figures.

Update these records in the same commit as the work they describe.

## Git synchronization

Each group should push only to its own repository (`origin`). The teacher repository is a read-only
remote named `upstream`:

```powershell
git remote -v
git remote add upstream <teacher-repository-url>
git fetch upstream
git merge upstream/main
git push origin main
```

Commit or temporarily set aside local work before merging. Teacher updates should normally affect
`notebooks/lessons/`, lesson assets, checks and documentation; group work remains under
`notebooks/project/`, `docs/` and `reports/`. Git still requires a person to resolve a conflict if
both sides changed the same lines.

## Verification gates

A change is ready only when all applicable checks pass:

1. `python scripts/verify_repository.py` reports no failures.
2. Every local notebook image reference resolves, or its notebook attachment decodes correctly.
3. The selected notebook uses the `icd-project` kernel and passes **Restart Kernel → Run All**.
4. Notebook assertions and documented reference counts pass.
5. Generated files occur only under `data/processed/` or `outputs/` and remain outside Git.
6. `git diff --check` reports no whitespace errors and `git status` contains only intended changes.
7. A clean clone can be set up and run using this README without asking the author for missing steps.

## Clean-clone test

Test a release in a different folder, not in the working repository:

```powershell
git clone <group-repository-url> clean-clone
Set-Location clean-clone
python scripts/verify_repository.py
conda env create -f environment.yml
conda activate icd-project
python -m pip install -e .
```

The first verification may warn that the excluded raw CSV files are absent. Obtain the documented
versions, place them in `data/raw/`, rerun the verification, create the group notebook, and use
Restart Kernel → Run All. Compare the regenerated statistics and figures with the documented
reference values.

## Limits and decisions

- The 2026 records may be incomplete; the extraction date is unavailable.
- `publication_id` identifies publications. An authorship row represents one publication–researcher relationship. Joining the two tables increases row count; joined rows are not a count of publications.
- The W06 analysis does not alter the input CSV files. The one-off `R093` group correction is documented above; `data/processed/` and `outputs/` contain regenerable results. Git records code, documentation, lesson assets, and notebooks while excluding source data without documented redistribution rights, local environments, secrets, and generated results.
