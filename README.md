# Introduction to Data Science project repository

This is the reference project structure for the Introduction to Data Science course. It combines
teacher-maintained practice material with a protected area where each student group develops its
own analysis. The current case study uses GOVCOPP publication data from 2020–2026, but the
organisation and workflow are intended to support the complete course project.

Open the repository root as the project folder. All analytical paths are built from that root.

## Purpose and ownership

Keeping teacher material and group work in different locations allows the teacher to publish
updates without silently replacing student work.

| Path | Owner | Rule |
|---|---|---|
| `notebooks/lessons/` | teaching team | Canonical lesson sources; groups do not edit these files |
| `notebooks/project/` | student group | Group adaptations and project notebooks |
| `docs/`, `reports/` | student group | Decisions, contributions, evidence and written deliverables |
| `src/icd_project_aux/` | shared | Reusable code; add new modules where possible instead of changing lesson helpers |
| `data/raw/` | local input | Read but never edit by hand; files remain local |
| `data/processed/`, `outputs/` | generated | Recreate with code; never retouch generated files |

## Structure

```text
projICD2627_/
├── README.md                       project overview and working conventions
├── environment.yml                 reproducible conda environment
├── pyproject.toml                  local Python package definition
├── data/
│   ├── raw/                         local source data; never edited by notebooks
│   └── processed/                   analytical datasets generated by code
├── notebooks/
│   ├── lessons/                     teacher-maintained notebooks
│   │   └── _assets/                 versioned images used by lesson notebooks
│   └── project/                     group-owned notebooks
├── src/
│   └── icd_project_aux/             reusable Python functions
├── outputs/
│   ├── lessons/<lesson-id>/         generated lesson results
│   └── project/<lesson-id>/         generated group-project results
├── docs/
│   ├── research_plan_v0.md          research question, design and risks
│   ├── evidence_register.md         claims and supporting evidence
│   ├── contributions.csv            group contribution record
│   ├── ai_use_log.csv               AI-use and verification record
│   ├── git_github_guide.md          beginner student workflow
│   └── git_github_teacher_setup.md  teacher-only repository setup
├── reports/                         group-written deliverables
└── scripts/                         setup and repository checks
```

Static images used by lesson notebooks live beside them in `notebooks/lessons/_assets/`; they are
versioned source material, not generated output. Each lesson writes to its own subfolder under
`outputs/lessons/`. Group notebooks belong in `notebooks/project/` and should write generated
results under `outputs/project/`.

## Set up the environment

Open the project root in VS Code. In a terminal at that root, run:

```powershell
conda env create -f environment.yml
conda activate icd-project
python -m pip install -e .
python -m ipykernel install --user --name icd-project --display-name "Python 3 (icd-project)"
python -c "import sys; print(sys.executable)"
python -c "from icd_project_aux.data import read_table; print(read_table.__module__)"
```

The `icd-project` environment installs the `icd_project_aux` helper package from `src/`.

If `environment.yml` changes, run `conda env update -f environment.yml --prune`. In VS Code, select the `icd-project` interpreter and notebook kernel. Check that `sys.executable` in the notebook points to the same environment.

## Create the group working notebook

Do not edit the canonical notebook in `notebooks/lessons/`. Create a group-owned copy with:

```powershell
python scripts/start_group_notebook.py W06S01 group-name
```

This creates `notebooks/project/W06S01_group-name.ipynb`, clears teacher execution results, points
static image references back to the lesson assets, and changes the generated-output destination
from `outputs/lessons/w06/` to `outputs/project/w06/`. The command refuses to overwrite an existing
group notebook.

## Data

Keep original inputs under `data/raw/` and treat them as immutable. The
[raw-data description](data/raw/README.md) records the current teaching files, units of observation,
formats, provenance, fingerprints and known limitations. Obtain any non-distributed files through
the channel designated by the teaching team and place them in `data/raw/` without opening and
resaving them.

Write cleaned, joined or otherwise transformed datasets to `data/processed/`. Every transformation
must be reproducible from code; do not use the processed directory as a place for manually edited
copies. When a new dataset is introduced, update its data description before using it in an
analysis.

## Run order

1. Open the repository root in VS Code.
2. Create or update the `icd-project` environment and install the package with `python -m pip install -e .`.
3. Put the documented source files in `data/raw/` and run `python scripts/verify_repository.py`.
4. Create the relevant group notebook from its lesson source, if it does not already exist.
5. Open the group notebook with the `icd-project` kernel and confirm `sys.executable`.
6. Use **Restart Kernel → Run All** and resolve the first failing checkpoint, if any.
7. Inspect the generated files under `outputs/project/`; do not edit them by hand.
8. Update the research, evidence, contribution and AI-use records in `docs/`.

## Generated and reference outputs

Everything under `outputs/` is regenerable and is not part of the distributed project material.
Correct the code and rerun the workflow instead of retouching a CSV or figure in place. If the
course later distributes selected small reference
results, store them separately under `reference/expected_outputs/<lesson-id>/` with a README that
states how and from which input version they were produced.

## Project records

- `docs/research_plan_v0.md` states the question, units of analysis, data, strategy and risks.
- `docs/evidence_register.md` links each claim to an output, unit, denominator, check and limitation.
- `docs/contributions.csv` records who performed and checked each contribution.
- `docs/ai_use_log.csv` records the request, resulting change, independent check and decision.
- `reports/` contains written deliverables, not generated analytical tables or figures.

Update these records whenever the work they describe changes.

## Verification gates

A change is ready only when all applicable checks pass:

1. `python scripts/verify_repository.py` reports no failures.
2. Every local notebook image reference resolves, or its notebook attachment decodes correctly.
3. The selected notebook uses the `icd-project` kernel and passes **Restart Kernel → Run All**.
4. Notebook assertions and documented reference counts pass.
5. Generated files occur only under `data/processed/` or `outputs/` and can be recreated from code.
6. The project records describe the current question, evidence, contributions and use of AI.
7. A new working copy can be configured and run from the documented environment and data requirements.

## Reproducibility principles

- Treat the project, rather than an individual notebook, as the unit of work.
- Build paths from the project root; do not insert computer-specific absolute paths.
- Preserve raw inputs and record their provenance, units, formats and limitations.
- Generate processed data, tables and figures from code rather than editing them manually.
- Keep analytical decisions, evidence, contributions and AI use documented beside the work.
- Use **Restart Kernel → Run All** as the final notebook check.
- Keep source data without documented redistribution rights, local environments, secrets and
  generated results outside the distributed project material.
